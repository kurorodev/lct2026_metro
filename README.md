# Metro Guard

Metro Guard — исследовательский прототип для поиска потенциально опасных объектов в габарите пути по 3D LiDAR. Он читает ROS 2 bags, оценивает коридор движения, группирует точки препятствий, подтверждает наблюдения во времени и сохраняет результат для просмотра и разметки.

Проект **не сертифицирован и не предназначен для управления торможением**. Точный габарит поезда и независимая разметка ещё не предоставлены; поэтому возможны пропуски и ложные тревоги. Подробнее — в [ограничениях и отчётах экспериментов](docs/PROJECT_GUIDE.md#известные-ограничения) и [проверке нового бэга](docs/FAKE_SCENARIO_RESULTS.md).

## Быстрый старт

Нужны Python 3.8+, Bash и данные в формате ROS 2 bag. Для офлайн-обработки ROS 2 ставить не нужно.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-runtime.txt
python -m pip install --no-deps -e .
```

Путь к bag должен указывать на папку с `metadata.yaml` и SQLite-файлом `.db3`. Например, если `data/cloud_with_fake_obj.zst` уже скопирован в проект:

```bash
tar --zstd -xf data/cloud_with_fake_obj.zst -C data
python -m metro_guard.cli run data/cloud_with_fake_obj \
  --config config/mounted_lidar.json \
  --output outputs/cloud-mounted \
  --export-every 10 --preview-points 2000
```

Откройте просмотрщик:

```bash
python -m metro_guard.cli serve outputs/cloud-mounted
```

Перейдите на [http://127.0.0.1:8080](http://127.0.0.1:8080). В просмотрщике доступны 3D, вид сверху и сбоку, шкала времени, список детекций и ручная разметка кадров. Для остановки нажмите `Ctrl+C`.

Архивы данных намеренно не хранятся в Git. Их нужно получить отдельно; сведения о новом архиве — в [описании данных](docs/NEW_DATA.md). Повторный запуск в существующий каталог результатов не перезаписывает данные: выберите новое значение `--output` либо укажите `--overwrite` осознанно.

## Деплой на сервер

Для проверенной конфигурации **Ubuntu 24.04, 2 ГБ RAM и 20 ГБ диска** используется облегчённый образ и Docker Compose. На сайте серверный просмотрщик открывается по `http://SERVER_IP/` после освобождения порта 80 старым сайтом.

Полные шаги установки, переноса bag, запуска, обновления и устранения проблем находятся в [руководстве по деплою](docs/DEPLOYMENT.md). Перед началом проверьте свободное место: распакованный новый bag занимает около 6,9 ГиБ. Весь старый набор около 22 ГиБ на такой диск не поместится.

## Структура проекта

| Путь | Содержимое |
|---|---|
| `metro_guard/` | Декодирование облаков, геометрия, детектор, CLI, оценщик и ROS-узел |
| `config/` | Базовая, экспериментальная и калиброванная высотой LiDAR конфигурации |
| `tests/` | Тесты декодера, детектора, оценщика и публикации результатов |
| `scripts/` | Проверка bag, benchmark, ROS и серверные smoke-проверки |
| `docs/` | [Руководство по проекту](docs/PROJECT_GUIDE.md), [деплой](docs/DEPLOYMENT.md), анализ данных и отчёты |
| `Dockerfile` | ROS 2 Humble: ROS-узел, воспроизведение bag и RViz2 |
| `Dockerfile.server` | Облегчённая офлайн-обработка и серверный просмотр результатов |
| `compose.yaml` | Ограниченные по ресурсам обработчик и веб-сервис Nginx |

## Проверка

```bash
python -m unittest discover -s tests -v
```

Серверный интеграционный сценарий (нужен Docker с Compose):

```bash
./scripts/server.sh build
bash scripts/server_smoke.sh
```
