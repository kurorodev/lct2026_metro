# Metro Guard

**Metro Guard — прототип, который анализирует 3D-облака LiDAR и выделяет возможные препятствия в расчётном габарите железнодорожного пути.** Он принимает ROS 2 bags или поток `PointCloud2`, оценивает геометрию пути по данным сканера, группирует точки-кандидаты и сопоставляет их между кадрами. Результаты можно посмотреть в браузере или передать через ROS 2.

**Публичные ссылки:** [веб-демонстрация](http://111.88.155.2/) · [исходный код проекта на GitHub](https://github.com/kurorodev/lct2026_metro) · [презентация для жюри](presentation/Metro_Guard_ЛЦТ2026.pptx).

## Как работает решение

1. Читает `PointCloud2` из bag и извлекает координаты точек.
2. Оценивает положение рельсов и локальный коридор движения по форме облака; начальную высоту установки сенсора можно задать в профиле.
3. Ищет пространственные группы точек-кандидатов в пределах расчётного объёма.
4. Подтверждает повторяющиеся наблюдения во времени и формирует покадровый результат.
5. Показывает облако, кандидаты и статусы в веб-просмотрщике; для ROS 2 доступны отдельный узел и визуализация RViz.

Это геометрический baseline без обученной нейросети. Ценность прототипа сейчас — воспроизводимый путь от исходного bag до результата, исследование габарита и быстрый просмотр потенциальных тревог.

## Что проверено

- Детектор обработал 2 488 кадров из шести исходных bag и 1 510 кадров нового сценария — 3 998 сообщений суммарно.
- На десяти выбранных контрольных кадрах нового сценария профиль `mounted_lidar` сопоставил детекции со всеми десятью объектами; прежняя конфигурация не обнаружила один низкий предмет на рельсах. Это проверка выбранных кадров, **не** значение precision, recall или полноты событий.
- В отдельном ROS 2 bag-прогоне обработаны все 201 входное сообщение, а p95 задержки callback → результат составил 62,9 мс. Этот прогон проверял тракт ROS, не точность на живом поезде.
- Пройдены 20 автоматических проверок ядра.

Независимой разметки и утверждённого чертежа габарита состава пока нет. В двух контрольных случаях объект, обозначенный поставщиком как расположенный вне габарита, пересекает предварительную геометрическую границу. Поэтому нельзя достоверно оценить ложные тревоги и пропуски на всём проезде. Проект **не сертифицирован и не предназначен для управления торможением**. Подробные методика и оговорки приведены в [отчёте по новому сценарию](docs/FAKE_SCENARIO_RESULTS.md) и [экспериментах](docs/EXPERIMENTS.md).

## Локальный запуск

Для офлайн-анализа нужны Python 3.8+, Bash и ROS 2 bag. Устанавливать ROS 2 для чтения bag не требуется. Из корня клонированного проекта выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-runtime.txt
python -m pip install --no-deps -e .
```

Получите архив `cloud_with_fake_obj.zst` отдельно: большие записи не хранятся в Git. Если архив положен в `data/`, выполните:

```bash
tar --zstd -xf data/cloud_with_fake_obj.zst -C data
python -m metro_guard.cli run data/cloud_with_fake_obj \
  --config config/mounted_lidar.json \
  --output outputs/cloud-mounted \
  --export-every 10 --preview-points 2000
python -m metro_guard.cli serve outputs/cloud-mounted
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). В просмотрщике доступны 3D-облако, вид сверху и сбоку, переход по кадрам, список результатов и ручные метки. Остановить сервер можно сочетанием `Ctrl+C`. Архив содержит `metadata.yaml` и SQLite-файл `.db3`; свободное место для распаковки нового bag — около 7 ГиБ. Данные и порядок сцен описаны в [`data/README.md`](data/README.md).
